## 实现指引

### 技术选型（开工前必做）

评估候选方案，关注三点：① React 19 + TanStack SSR 兼容（滚动库常依赖 DOM，需确保水合后才激活，SSR 不报错）；② `prefers-reduced-motion` 降级；③ 长页面性能。

- **Lenis + Framer Motion `useScroll`/`useTransform`**：React 原生 hook 风格，与现有 React 19 契合，`useScroll` 天然支持滚动进度映射。推荐起点。
- **GSAP ScrollTrigger**：能力最强、复杂时间线表达力好，但与 React 集成需 `useGSAP`，且 bundle 更大。适合 Framer Motion 表达力不足时备选。

选定后在该 issue 对应 PR 描述里记录决策（理由 + SSR/reduced-motion 策略），供后续维护参考。

### 降级是硬要求

滚动驱动动画是无障碍重灾区。务必在 `prefers-reduced-motion: reduce` 时让首页退化为"可正常滚动的静态分区"——即所有内容仍按顺序可滚动浏览，只是失去联动动效。建议用一个 hook（如 `useReducedMotion`）集中控制，动画值退化为终态。

### 内容真实性

叙事中的文字应承载真实信息（站点统计、文章摘要、贡献数据），让叙事同时是"信息传递"，而非纯炫技。数据来源复用 loader 预取的 posts/github 数据。

### SSR 动态站的滚动实现

本项目是 SSR 动态站，数据客户端可达。滚动动画需用 React 滚动 hook（如 GSAP ScrollTrigger）在客户端水合后驱动，而非静态站构建期编排的方式。
