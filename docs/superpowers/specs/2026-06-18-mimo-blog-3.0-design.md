# mimo-blog 3.0 前端重构设计文档

## 1. 项目背景与目标

release/2.0 前端已迁移到 TanStack Start，但存在以下问题：

- 部分核心前台路由仍为 Placeholder，老页面组件遗留在 `pages/` 中。
- 视觉层、组件组织、代码规范不统一。
- 样式设计需要完全重新设计，不参考现有实现。

3.0 的目标是在保留后端全部功能的前提下，彻底移除并重建前端，建立更规范的架构、代码规范与界面设计。

## 2. 分支策略

- 从 `release/2.0` 切出 `release/3.0`。
- 删除 `web/` 和 `nginx/` 目录。
- 保留 `api/`、Docker Compose 配置、`scripts/`、CI、 secrets、`docs/` 等基础设施。

## 3. 技术栈

| 层级 | 技术 |
|---|---|
| 框架 | TanStack Start SSR + TanStack Router 文件路由 |
| UI 库 | React 19 + TypeScript 6 + Vite 7 |
| 样式 | Tailwind CSS v4 + shadcn/ui |
| 动画 | ReactBits（视觉特效）+ motion |
| 状态 | TanStack Query + Zustand |
| 表单 | React Hook Form + Zod |
| 质量 | Biome + Vitest + TypeScript --noEmit |
| 通知 | Sonner |
| 表格 | TanStack Table |
| 图表 | Recharts |

## 4. 代码规范

- 一个文件只允许写一个 React 组件。
- 单组件文件建议不超过 400 行，允许合理浮动，超过时拆分子组件到新文件。
- 表单验证统一使用 React Hook Form + Zod，所有校验逻辑收敛到 `features/<feature>/schemas/`，禁止手写 `if/else` 校验。
- 所有 interface/type 和 React props 属性必须写 JSDoc 风格注释。
- 状态/类型/角色等有限取值优先使用 `const` 对象 + `as const` 或 TypeScript enum。
- 禁止原生 `confirm` / `alert` / `prompt`，统一使用 shadcn/ui 的 `AlertDialog` 或 Sonner toast。
- 文件名规范：组件使用 PascalCase，hooks/utils 使用 camelCase，feature 目录使用 kebab-case。
- API 调用和 TanStack Query key 工厂集中在 `features/<feature>/api/`。
- 环境变量集中在 `lib/env.ts`，使用 Zod 校验，禁止业务代码直接使用 `import.meta.env`。
- 错误统一通过 Error Boundary 和 Sonner toast 展示。

## 6. 架构分层

- **app/**：全局入口、根布局、全局 Provider、全局样式、Error Boundary。
- **routes/**：TanStack Router 文件路由。每个 route 文件只负责数据预取、权限守卫、布局选择，页面 UI 委托给 `features/` 的 page 组件。
- **features/**：按业务领域划分，每个 feature 独立管理 api/、components/、hooks/、schemas/、types/、utils/。
- **components/ui/**：shadcn/ui 基础组件。
- **components/shared/**：跨 feature 通用组件，如 SEO、Pagination、ImageUpload、ErrorFallback。
- **components/reactbits/**：ReactBits 动画组件的封装与主题适配。
- **lib/**：纯工具函数、环境变量校验、日期格式化等。

## 7. 数据流

- **服务端状态**：统一用 TanStack Query。query key 工厂集中在 `features/<feature>/api/keys.ts`，mutations 统一在 `features/<feature>/api/mutations.ts`。
- **认证状态**：Zustand + persist 存储 token/refreshToken/user，SSR 时通过初始 props 或 cookie 避免 hydration 不匹配。
- **主题/侧边栏**：next-themes 管理主题，后台 sidebar 折叠状态用 Zustand。
- **表单状态**：React Hook Form + Zod resolver，schema 集中在 `features/<feature>/schemas/`。
- **Toast 通知**：Sonner 全局 toast。
- **环境变量**：`lib/env.ts` 集中校验。

## 8. SSR/CSR 边界

- TanStack Start 负责首屏 SSR。
- 浏览器专属组件必须在客户端渲染：
  - Tiptap 富文本编辑器
  - APlayer / Plyr 音乐播放器
  - CodeSandbox 嵌入
  - 部分 Three.js / WebGL 特效
- 通过 `lazy` + `Suspense` 延迟到客户端，SSR 时回退为占位或静态 HTML。

## 10. 后台管理设计

- **布局**：固定顶部 Header + 可折叠左侧 Sidebar + 主内容区；移动端 Sidebar 变为 Drawer。
- **权限**：进入 `/admin` 路由树前在 `beforeLoad` 中检查 `admin:access` 权限，无权限跳转登录或 403。
- **数据表格**：使用 TanStack Table + shadcn/ui Table，支持排序、分页、筛选、批量操作。
- **表单**：所有新增/编辑使用 Dialog/Sheet + React Hook Form + Zod。
- **图表**：仪表盘使用 Recharts 展示访问趋势、文章分布等。
- **文件上传**：媒体库和封面图使用基于 react-dropzone 的拖拽上传，调用后端 `/media/upload`。
- **删除确认**：禁止原生 confirm，统一使用 AlertDialog。

## 11. 复杂模块

### 11.1 富文本编辑器

- 使用 Tiptap + 自定义工具栏。
- 必须在客户端渲染，SSR 时回退为静态 HTML 或占位。
- 支持图片、链接、代码块、Markdown 导入/预览。

### 11.2 音乐播放器

- 保留 APlayer / Plyr 双版本切换，通过 `/music/settings` 配置。
- 播放器组件客户端懒加载。

### 11.3 表情系统

- Bilibili 风格表情分组、上传、选择器。
- 评论内使用 `sticker-in-comment` 类渲染。

### 11.4 CodeSandbox 嵌入

- 文章内支持嵌入沙盒，组件客户端渲染。

### 11.5 GitHub 集成

- 关于页展示贡献图和 Pinned Repos。
- 使用 GitHub API 或后端代理。

### 11.6 SEO

- 每页使用 Seo 组件注入 meta 标签和 JSON-LD。

## 12. 测试与质量

- **单元测试**：Vitest + @testing-library/react + jsdom，重点覆盖 `lib/`、`features/<feature>/api/`、`hooks/`。
- **类型检查**：`pnpm typecheck`（tsc --noEmit）作为 CI 强制步骤。
- **代码质量**：Biome 负责 format 和 lint，配置为严格模式，提交前自动修复。
- **E2E**：可选 Playwright 覆盖核心用户流程，首期不强求。
- **CI**：GitHub Actions 并行运行 typecheck、Biome、Vitest、build。

## 13. 实施原则

- 保留后端 API 契约不变。
- 不参考现有前端样式设计。
- 优先完成核心前台与后台框架，再迁移复杂模块。
- 每次提交保持小而原子，遵循 Conventional Commits。
