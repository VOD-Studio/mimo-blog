# PRD：前台视觉改版（三套主题 + 排版强化 + 滚动叙事首页）

## Problem Statement

前台当前是单一「霓虹紫蓝」视觉身份：`--neon-*` 调色板、辉光 glow、`ParticleField` 粒子场、`SpotlightCard` 聚光卡。这套身份无法满足多场景表达诉求——它只服务于一种"赛博科技"气质。

同时首页是静态分区堆叠（`LandingHero` + 公告/最新文章/开源贡献/项目四块纵向罗列），缺乏叙事节奏，首屏之后没有引导用户继续探索的视觉钩子。

本次改版要解决两件事：

1. **主题系统**：从单一霓虹身份升级为可切换的多主题体系，提供三套性格鲜明的视觉预设（原神·璃月 / 绝区零 / 中性），每套各含明暗，用户自由选择。
2. **首页重做**：把静态分区首页重做成一段滚动驱动的视觉叙事，让首页成为站点的"开场镜头"而非目录页。

排版层面，强化 Maple Mono 等宽字体在细节处（标签、导航、计数、时间戳）的使用，建立"等宽细节 + 正文衬线/无衬线"的字体节奏。

## Solution

### 一、主题系统：风格 × 明暗 二维解耦

现有 next-themes 只管**明暗**（`attribute="class"`，`.dark` 类切换）。本次引入第二个独立维度——**风格（palette）**，通过在 `<html>` 上叠加一个风格类（`theme-genshin` / `theme-zzz` / `theme-neutral`）实现，与 `.dark` 正交。

```
<html class="theme-genshin">        ← 璃月·亮
<html class="theme-genshin dark">   ← 璃月·暗
<html class="theme-zzz dark">       ← 绝区零·暗
<html class="theme-neutral">        ← 中性·亮
```

CSS token 定义结构：

```css
/* 默认中性（无风格类时兜底，等同 theme-neutral） */
:root { --primary: ...; --accent: ...; }

/* 风格亮色覆盖 */
:root.theme-genshin { --primary: 璃月金; --accent: 璃月棕; ... }
:root.theme-zzz     { --primary: 荧光黄绿; ... }

/* 风格暗色覆盖（.dark 与风格类同时存在） */
:root.theme-genshin.dark { ... }
:root.theme-zzz.dark     { ... }
```

这样动效组件只需引用 `--primary` / `--accent` 等语义 token，glow 辉光色、`SpotlightCard` 聚光色自动随主题变化，无需组件层改动。

### 二、三套配色方案

均用 OKLCH 色彩空间定义，保证明暗两模式下对比度达标（正文 ≥ 4.5:1）。

| 预设 | 气质 | 主强调色 `--primary` | 次强调色 `--accent` |
|------|------|---------------------|---------------------|
| **原神·璃月** | 稳重温暖、金石质感 | 璃月金（暖金） | 璃月棕（岩土棕） |
| **绝区零** | 酷炫高对比、街头感 | 荧光黄绿（acid lime） | 深黑背景 + 高饱和点缀 |
| **中性** | 克制通用、当前主体 | 近黑/近白（随明暗） | 中性灰 |

具体 OKLCH 数值在「实现决策」中给出基线，最终值在 issue 实现时用对比度工具校准。

### 三、首页滚动叙事

废弃当前 `routes/index.tsx` 的静态分区结构，重做为一段多场景滚动叙事。首页由若干"场景（scene）"组成，场景随滚动进度联动变换。结构：

1. **Hero 场景**（首屏）—— 取景器风格四角边框 + 流体大字品牌名（`clamp()` 响应式字号）+ 状态脉冲。入场即建立视觉基调。
2. **Ticker 场景** —— 跑马灯滚动文字带（站点标语 / 最新文章标题轮播），作为场景间的过场节拍。
3. **图像数据面板场景** —— 滚动触发的图像/卡片面板，展示最新文章（内容驱动，非装饰）。
4. **场景联动叙事** —— 多图层随 `scrollDistance` 联动：竖线 → 柱体 → 文字浮现 → 柱体全屏展开 → 过渡到下一场景。这是首页的视觉高潮。

技术选型（在 issue 内最终确定）需满足：React 19 + TanStack SSR 兼容、`prefers-reduced-motion` 降级、长页面性能可控。候选：Lenis（平滑滚动）+ Framer Motion `useScroll`/GSAP ScrollTrigger。

### 四、排版强化

- 主字体保留 Maple Mono（已是 `--font-mono`）。
- 细节处显式启用等宽：导航项、分区序号、计数（"12 篇文章"）、时间戳、标签 pill、Hero 跑马灯文字，统一加 `font-mono` + 适度字间距（`tracking-*`）。
- 建立「正文用无衬线系统栈 + 细节用 Maple Mono 等宽」的双层字体节奏。

## User Stories

### 主题系统

1. 作为访客，我想在原神·璃月 / 绝区零 / 中性三套主题间一键切换，这样站点视觉能匹配我的偏好
2. 作为访客，我切换主题时想看到流畅的圆形扩散过渡（复用现有 View Transitions），这样切换不突兀
3. 作为访客，我选择的主题（含风格 + 明暗）要被持久化，这样下次访问保持一致
4. 作为访客，每套主题都能独立切换明暗，这样我在不同光线下都舒适
5. 作为访客，三套主题下正文对比度都要清晰可读，这样长时间阅读不疲劳
6. 作为访客，辉光、聚光卡等动效颜色要随主题强调色变化，这样视觉身份统一

### 首页滚动叙事

7. 作为访客，首屏我想看到取景器风格的大字 Hero，这样立刻感受到站点的视觉调性
8. 作为访客，我想向下滚动时看到多个场景联动变化（竖线变柱体、文字浮现、全屏展开），这样首页像一段视觉叙事而非目录
9. 作为访客，滚动中出现的图像数据面板要展示真实文章内容，这样叙事同时传递信息
10. 作为访客，我想在场景间看到跑马灯 Ticker 过场，这样滚动节奏有呼吸
11. 作为访客，我开启了"减少动效"系统设置时，首页应降级为可正常浏览的静态版，这样无障碍可用
12. 作为访客，首页滚动叙事在三套主题下都要视觉协调，这样主题切换不影响首页体验

### 排版强化

13. 作为访客，我想看到导航项、计数、时间戳等细节用等宽字体，这样界面有"工程感"的排版节奏
14. 作为开发者，等宽细节字体通过 `font-mono` 工具类统一应用，这样维护一致

## Implementation Decisions

### 主题 token 架构

- **风格维度独立于明暗维度**。风格由 `<html>` 上的 `theme-genshin` / `theme-zzz` / `theme-neutral` 类表示，明暗仍由 next-themes 的 `.dark` 管理。无风格类时兜底为中性。
- **持久化**：风格选择存入 cookie（与 next-themes 的明暗 cookie 并列），SSR 读取防 FOUC。
- **语义 token 全部参数化**：`--primary` / `--accent` / `--ring` 等在各风格类下重新赋值。组件只引用语义 token，不硬编码颜色。
- **辉光与聚光色绑定强调色**：`--glow-soft`（现 `220 90% 60%`）等遗留变量改为派生自当前主题 `--primary`，使 glow/SpotlightCard 自动适配三套主题。

### 三套配色 OKLCH 基线

（最终值在实现时用对比度工具校准，以下为目标方向）

**原神·璃月**
- 亮：`--primary: oklch(0.68 0.13 75)`（暖金），`--accent: oklch(0.45 0.06 55)`（岩棕）
- 暗：`--primary: oklch(0.78 0.14 75)`（亮金），背景偏深褐 `oklch(0.18 0.02 55)`

**绝区零**
- 亮：`--primary: oklch(0.82 0.20 125)`（荧光黄绿），背景纯白，强对比
- 暗：`--primary: oklch(0.85 0.21 125)`，背景近黑 `oklch(0.12 0 0)`，高饱和点缀

**中性**（继承当前调色板的灰阶主体，去除霓虹默认）
- 亮：`--primary: oklch(0.205 0 0)`，`--accent: oklch(0.556 0 0)`
- 暗：`--primary: oklch(0.922 0 0)`，`--accent: oklch(0.708 0 0)`

### ThemeToggle 扩展

- 现有 `widgets/ThemeToggle/variants/` 有 7 种切换器视觉变体。本次扩展其语义：从「明暗切换」升级为「风格 + 明暗」切换。
- 推荐方案：风格选择用一个新的选择器（如下拉/段控/饼菜单），选定风格后，明暗仍由现有切换器管理。即风格与明暗是两个独立控件。
- 切换风格同样复用 `animateThemeRipple` 圆形扩散 View Transition。

### 首页滚动叙事实现

- **场景化架构**：首页拆为多个 Scene 组件（`HeroScene` / `TickerScene` / `DataPanelScene` / `NarrativeScene`），各 Scene 自包含滚动动画逻辑。
- **内容驱动**：图像数据面板从 `fetchPosts` 取真实文章，不写死装饰图。
- **降级**：`prefers-reduced-motion: reduce` 时，关闭场景联动动画，退化为可正常滚动的静态分区（保证内容可达）。
- **SSR**：首屏 Hero 必须 SSR（首屏直出），下方场景可客户端水合后激活滚动动画。
- **数据预取**：沿用现有 loader 模式，SSR 预取文章/公告/贡献到 React Query。

### 排版细节落点

- 导航项 `HeaderNav`：`font-mono` + `tracking-wide`
- 分区序号/计数（"最新文章"旁的篇数）：`font-mono` + `text-muted-foreground`
- 时间戳（PostCard 相对时间）：`font-mono`
- 标签 pill：`font-mono` + `tracking-tight`
- Ticker 跑马灯文字：`font-mono`

## Testing Decisions

### 测试原则

- 主题 token 是纯 CSS 变量，无运行时逻辑，不单测。
- 测外部行为：切换主题后 DOM class 正确、cookie 写入、SSR 防闪烁。
- 首页滚动动画测降级行为（reduced-motion 下不报错、内容可达），不测具体动画帧。

### 测试 Seam

| Seam | 层级 | 覆盖 |
|------|------|------|
| 主题切换集成测试 | widget 组件 | 选风格 → `<html>` 有对应类 + cookie 写入；明暗独立切换 |
| 首页降级测试 | route 组件 | `prefers-reduced-motion` 下渲染无错、文章内容可见 |
| 对比度 | 视觉回归（手动/Storybook） | 三套主题明暗共 6 变体的正文对比度达标 |

## Out of Scope

- **后台视觉改版**：本次只动前台，后台（`/admin`）布局与主题不动。
- **文章列表/详情页布局重做**：本次布局调整仅限首页。文章列表、详情页保持现有布局，只随主题 token 自动适配配色。
- **透明无阴影卡片 / 方角反色标签 / 可收起胶囊导航**：这些结构美学风格本次**不引入**。卡片、标签、导航保留现有形态，仅配色与字体细节更新。
- **页眉/页脚结构重做**：Header/Footer 保留现有结构，仅排版细节（字体/间距）微调。
- **新页面**：不新增归档/分类/相册等页面。
- **i18n**：不做多语言。
- **主题编辑器**：用户只能选预设的三套，不能自定义调色。

## Further Notes

### 与现有 View Transitions 的协同

页面导航 VT（forward/back/fade）作用于 root 快照，主题切换 VT 用圆形扩散并抑制命名组（`html.theme-vt`）。风格切换复用主题切换的圆形扩散路径，不引入新 VT 类型。三套主题切换不应触发页面导航 VT。

### 向后兼容

- 中性主题设为默认（兜底），保证未迁移的页面在无风格类时仍正常。
- 现有 `--neon-*` 变量保留（仍用于强调），但默认主体配色由语义 token 驱动，逐步降低对 neon 的直接依赖。
- Maple Mono 字体加载不变，仍是 `@fontsource/maple-mono`。

### 分期建议

主题系统（token + 切换器）是基础设施，应最先完成；排版细节可与主题并行；首页滚动叙事依赖主题 token 就绪后进行，作为最后一块。三者解耦后可独立 issue 并行推进。
